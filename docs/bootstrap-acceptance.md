# 私有空仓的单次初始化验收

`sync-managed.yml` 的 `bootstrap_only=true` 仅用于经批准的单次私有空仓验收。它保留原生中央 Run、治理身份及 `steward-governance-mutation` 并发组，跳过模板递送和健康作业，不开启 `STEWARD_TEMPLATE_APPLY`。普通运行仍使用原有开关与安装范围。

准确目标通过私有管理员仓 `steward-settings` 的受审默认分支文件 `acceptance/bootstrap-target.json` 指定：`schemaVersion: 1`、一个正整数 `repositoryId`、`purpose: "bootstrap-only"`。这是单次验收控制，不是常驻仓库目录。目标必须仍在治理 App 安装范围内、私有、未归档且可用。中央的公开输入、环境和输出不包含目标标识；读取使用只限管理员仓的 contents:read 短令牌，随后撤销。解析失败只返回固定错误。

正式执行前保存安装范围、所有 refs、目标恢复变量、规则完整对象及私有控制文件的准确提交。初始化复用既有 `bootstrapRepository`：保存恢复变量，必要时仅排除准确目标，创建首提交，恢复保护，归档后清理变量。规则18883080与26650622的职责摘要固定在配置中；18883080的唯一中央 Native Validation 条目 SHA 必须等于本次已核验中央 Run 的 controller SHA，摘要仅规范化该字段，其他 required workflows、条件、规则、路径、来源仓和绕过主体均保持约束。旧恢复记录继续核验其真实来源及祖先关系，以当前受信版本恢复；源码变化不免除规则核验。

单仓入口在申请目标写令牌前用独立 metadata:read 令牌重新核验目标身份、私有状态和可用性；核心初始化在任何写入前再次核验。GitHub 不提供跨仓库元数据与规则写入的原子事务，验收窗口须避免并发可见性调整。私有依赖检查仅认可准确控制路径，并复用相同三字段解析器；额外字段、其他控制文件和超长内容均不通过。采用顺序为中央实现及可信版本先行，随后私有控制 PR 在新版本下重新通过全部检查。

若留下恢复变量或临时排除，先对账再重跑相同入口。保留私有控制文件直至保护、首提交和归档均真实核验通过，不能因过期或清理阻断恢复。正常模板写者未启用时没有定时恢复承诺；持续失败由维护者按准确 Run 和恢复记录处理。完成后通过受审私有 PR 删除一次性控制文件，历史和归档保留；以后使用该入口须重新明确目标与授权。

恢复记录的规则ID集合必须与当前绑定完全相同；旧空集合、缺项或额外规则均在写入前以 RECOVERY_RULE_BINDINGS_CHANGED 拒绝并保留原变量。不能自动补造旧排除项的所有权，也不能跳过新增规则。改变规则集合前须先完成已有恢复；发现历史不匹配记录时，由维护者对账实际保护和原始记录并准备受审迁移，不直接删除变量或声称恢复成功。仅可信源码SHA提升、规则集合及职责不变时仍可继续恢复。

成功只表示首提交、保护恢复及治理状态归档通过。Copier 文件递送、采用 PR、完整新仓治理接入和产品功能分别验收；本入口不授予旧文件递送 App 新仓访问，也不启用发布、模型、站点或新的周期调度。
