# 正式发布正文

正式模板的中央来源是 `templates/repository/.github/release-template.md.mustache`。候选作业从已采用的固定控制器提交读取模板和渲染器，将中文版本区段写进 Release PR 首页。维护者在合并前可直接修改该区段。受信合并事件保存完整 PR 正文和正式区段的摘要。

候选和正式发行使用项目名、空格和本版标签作为标题，例如 LayerScape v1.1.1。正文从本版实质内容开始。候选作业将模板全文作为请求字段 `organizationTemplate` 传给 Copilot，并用同一份内容渲染返回的段落。模板文案和排版随中央模板更新。发行说明以中文为主体语言，结合项目用途和实际变更选择对使用者有意义的内容。顶部「审阅提示」说明如何在 PR 首页描述中编辑发行说明。发行说明默认展开，用于正式草稿。底部「PR 信息（仅供审阅）」使用同样的引用样式，默认折叠；展开可查看项目附注、候选文件差异和来源记录。能从已归档的候选确认创建时的变更范围时保留该快照。较早的候选缺少此记录时展示本轮来源。

正文须至少包含一项本版实质内容，由系统附上与固定源码绑定的版本记录。必须执行的操作居首，概述与本版重点择一。其后按适用性展示本次更新、兼容性与迁移、已知问题与限制、贡献者和版本记录。单项修复可直接写入错误修复。只影响兼容性时可直接填写兼容性与迁移。

预览正文按适用性填写 `必须执行的操作`、`概述`、`本版重点`、各更新分类、`兼容性与迁移` 或 `已知问题与限制`。概述为单行段落，其他栏目中的每项以 `**短标题**。具体说明` 开头，条目用空行分隔。说明可以包含公开 HTTPS 链接。贡献者与版本记录由候选作业加入。

候选中指向本仓源码、附件和工作流的获取说明使用本版 tag。版本记录使用候选时核实的本版比较或固定快照链接。合并定稿中的链接随正文进入正式页。

文档本身属于交付，或实质修订会影响本版读者判断或操作时，才填写文档更新。生成器通过版本区间中的文档原文或文本差异取证，并由候选审阅确认使用者影响。普通 README 维护、文件位置、标签和提交标题可用于定位变化。安装、升级与引用要求应写在读者对应的操作栏目，并链接细节。

条件模板适用于纳入 SPLRAD 治理的组织仓。新周期按上一版边界至本版受审源码的实际变更，从 GitHub 读取 commit author 并按数值 ID 去重。仅执行提交或合并的账号、机器人、可识别的服务账号和 GitHub 平台账号从名单排除。符合条件的贡献者以可点击的 48 px GitHub 头像展示。当前模板在折叠区仅列出链接到个人主页的 GitHub 用户名，名单为空时省略整节。

双父合并提交以实际合并结果相对 Git 自动重做结果的差异确定贡献范围。多于两个父提交的合并沿用各原始提交的作者；浅克隆须补齐历史后才能生成新的贡献者名单。

已审定的旧候选、人工稿和历史周期使用受保护记录中的作者、已审名单和原模板。候选交接和冻结恢复核对同一份受保护记录，并保持原正文格式。

候选 PR 以 HTML 注释保留 Release Please 解析单项目版本所需的数字标题。官方 Action 创建草稿后，Steward 核对草稿身份及原生正文，写入项目标题和审定正文，并回读核验。随后用产品工作流的实际交付包补件。原生投递回执绑定工作流、Run、attempt、制品 ID 和摘要。公开和恢复沿用同一 Release ID、正文和已核验文件。历史封存正文及签名附件继续按原格式读取和验证。

仅修订公开正文时，产品在受保护的默认分支采用 `.release-notes/published/<releaseId>.md`。文件首行使用 `<!-- release-body [仓库数字ID,发行数字ID,"tag","源码SHA","原始正文SHA256"] -->`，紧接换行及完整新版 Markdown。历史签名正文以原附件摘要核验。验证器在固定默认分支提交读取该路径，验证最近修改该文件的提交签名、文件字节和对应发行身份。网页采用首行之后的正文，附件、签名和历史生产回执继续按原件验证。
