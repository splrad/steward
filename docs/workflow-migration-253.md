# Steward #253 受控工作流迁移

## 生效方式

默认分支的可信验证器继续要求工作流集合与 repositories.json 完全一致。仅在集合不一致时读取同一可信策略检出中的 config/workflow-migration.json；候选仓库不能提供授权记录。

本记录只授权 splrad/steward（1296724484）的同仓 PR #253 → main，截止 2026-11-03 00:00 UTC。记录固定原允许集合及新集合全部 11 个工作流的 SHA-256，来源为已复审提交 ab3cddd7727917284084899397f161c3d31a0161 的 Git blob。摘要覆盖完整内容，校验拒绝非普通文件及未提交改动。使用 Git blob 避免 Windows 检出换行转换造成误判。

记录只替代本次路径集合匹配，后续配置、测试、类型、dist、actionlint、规则指引及片段检查照常执行。其他 PR、其他仓库、fork、过期记录、额外或缺失路径、任何已授权文件内容变化均拒绝。不要把两个集合取并集，也不要让候选策略成为可信策略。

前置 PR 本身保留原工作流集合和现有 repositories.json，因此仍须通过当前 main 的验证器、审查和人工批准。前置 PR 合入后同步 #253 基础分支，检查运行实际策略 SHA 和完整任务结果；若出现其他旧策略兼容问题，应单独取证处理，不能把本次授权扩大为整套验证豁免。

#253 合入后，新 repositories.json 清单成为默认集合；随后通过普通受审 PR 删除迁移记录、临时验证模块及测试，并恢复单一精确集合入口。超期未完成则关闭此次授权，延期必须通过新的策略审查。

## 部署隔离：合并前置条件，尚未执行

检查时 steward-deployment 环境仅有 main 分支限制，没有 required reviewers。现有部署工作流在 main 上的 config/** 或 packages/runner/** 等变更后自动运行。因此合入此前置 PR 会触发部署，不能仅依赖“不手动 dispatch”来隔离。

由获授权的管理员在合并前配置 steward-deployment 环境：保留 main 分支限制，增加独立维护者的 required reviewers，禁止自审批，并禁止管理员绕过环境保护。核验所有部署与远程 D1 迁移步骤都在该环境作业内；若账户能力不支持这些保护，则不得合并，需先另行审查代码级部署隔离方案。

环境设置变更需另行授权。本 PR 不修改线上设置、部署工作流、数据库或运行时。批准 PR 合并不等于批准等待中的环境部署。前置策略无需部署 Worker 即可由规则集指定的 main 工作流读取；部署保持待审批，直到完整运行时及数据库迁移获得单独授权。

## 验收

- 前置 PR 原工作流集合精确匹配，既有门禁正常执行。
- 迁移正向通过；仓库/PR/base/fork/期限/原策略/路径/内容/模式/脏检出/候选自授权反向用例失败。
- 迁移匹配后仍执行验证任务，任务失败不转换为成功。
- #253 后续运行读取已合入可信策略，且仍需完成全套检查和当前 head 审查。
- 合并前回读环境保护；未经部署授权不批准环境作业。
