# 质量来源的 Markdown 与 HTML 分段

质量输入保留完整原始评论、原生 ID、提交、链接和严重级别。Markdown 与 HTML 混合评论中的普通 HTML 正文也需要转述，不能把所有 HTML 节点当作代码块跳过。

`prepareQualitySource` 先识别 Markdown 代码、链接及实际 HTML 节点；仅将 Markdown AST 确认的 HTML 范围交给 parse5，其余位置等长遮蔽，防止转义标签和链接目标被误认成 HTML。parse5 SAX 的词法位置覆盖 fragment DOM 会忽略的 body/html/head 和孤立表格标签，供标签原子性与语言边界使用；DOM 位置仍用于代码范围。Markdown 代码块、HTML `pre`、`script`、`style` 及注释按原始字节保留；普通 HTML 标记及其中的正文继续留在输入中，不重新序列化 DOM，也不按浏览器纠错后的节点顺序重排原文。行内代码与链接作为不可拆分片段处理，原始 HTML/Markdown 链接字面值加入 `originalIdentifiers`，输出必须逐字返回。未闭合或孤立的普通 HTML 标记仍保留在原文输入中。

语言判断忽略代码、标记及链接目标，但保留链接标签及 HTML 正文，并以 HTML 标签位置区分独立语言单元，包含 span 等行内标签中的英文说明及 form、fieldset、textarea 等容器。短段落在一个不超过 6 KiB 的片段内组合，逐字保留原始 CRLF、段落分隔及空白。长正文按语句、必要时按 Unicode 码点切分；普通 HTML 标签本身也不可拆分，属性内标点不作为分句位置（外层元素可跨片段，不伪造包装标签）；超过单片段容量的不可分代码/链接不截断，停止并返回输入限制错误。纯空白尾片段与相邻正文在安全原子边界重新分配，确保持久化片段非空且不改写分隔字节；若完整不可拆分原子加空白不存在合法有界切分，则按输入限制停止。纯代码或已可读的中文来源不调用模型，仍呈现完整原文。

每批最多 10 项、输入 JSON 最多 24 KiB、闭合输出 Schema 及逐项身份/覆盖校验保持不变。实际调度仍须先计算完整来源的片段数及批大小；一条来源不等于一次请求。

## 缓存兼容性

新 `qualitySegmentKey` 将 `markdown-html-v2` 分段器版本加入摘要，其他来源、正文、配置版本、片段序号和标识绑定保持。即使调用方未改变 `configVersion`，新片段也不会命中旧算法的缓存键。

`reconcileQualitySources` 为当前 head 建立新键集合，保留已有 `entries`、结果和尝试回执；受保护状态分支的 Git 历史保留旧 head 快照。旧片段不能凭相同 `segmentIndex` 进入新结果。当前新片段生成完成后，同一算法、来源与配置的再次观察仍可复用新缓存。旧缓存可以解码；直接绕过 reconcile 调用新翻译器处理旧键会在键校验处停止。

新一批验收还应使用明确的新 `configVersion`，绑定实际已采用 controller、准确 PR head/base、完整来源摘要及最新治理 state。调整分段器不重置已经发生的调用计数，不删除旧的部分成果，不构成额外模型调用授权。

公开原生评论 `review-comment:4505551497` 是回归夹具：812 UTF-8 字节，包括行内链接/代码及末尾 HTML 段落。离线测试要求完整原文进入有界批次、末段不遗漏、代码及链接字面值不丢失，并覆盖嵌套/不完整 HTML、纯代码、混合语言和长文本边界。离线假客户端只验证完整覆盖、持久化与去重，不替代真实模型验收。
