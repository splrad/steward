# 审查指令的维护与采用

## 公共来源与入口设置

中央维护者必须在 [AGENTS 模板](../../templates/repository/AGENTS.md) 维护完整公共审查规则。各仓根 AGENTS.md 必须与所采用模板版本的全文一致。

[Copilot 组织稿](copilot-organization.md) 必须保存审查语言条款，组织 Custom instructions 与 Codex 应用 Review instructions 必须采用相同正文。组织设置保存后回读正文和适用范围；当前应用设置及人工入口采用已记录的用户确认。

项目事实和合同保留在各仓已有配置、源码、脚本、测试及有效技术文档中。公共审查模板不得固化逐仓变化的版本、模块、命令或产物数量。

## 模板采用与迁移

仓库更新必须使用已审模板版本和现有 Copier 递送流程。采用记录必须绑定模板来源、Git 提交及真实 Copier answers；验证预期值必须来自受信控制器，候选变更不得自行提供放宽校验的预期值或验证器。

首次采用前，必须保存原文并盘点完整 Git tree 中适用的指令载体。每项有效内容必须确定保留位置和验证依据，再形成完整采用差异。读取失败应单独记录；原文件仅在内容迁移、消费者处置和恢复条件均满足后退役。

周期更新必须使用 Copier update。出现冲突时应停止受影响递送、保留现场及人工修改，并在原采用流程中解决；不得通过强制覆盖或手工改写 answers 消除冲突。

## 安全政策

在 [公共安全规则](security-common.md) 修改组织报告政策及通用安全审查指南。模板递送使用所选正式标签中的正文，只替换根 SECURITY.md 的 `<!-- BEGIN SPLRAD COMMON SECURITY -->` 和 `<!-- END SPLRAD COMMON SECURITY -->` 两行之间的内容。管理员通过普通仓库 PR 在“项目特有规则”中编辑本仓约束。首次遇到无标记旧政策时，管理员先审阅其分区迁移。标记异常或公共正文被本地改写时，递送停止，修复后从最新分支重试。中央仓已经采用带公共规则的标签后，先通过中央 PR 修改公共源，根文件仍可保留已采用标签的正文；待新标签发布，再由递送 PR 更新根文件。

只采用安全政策时，使用正常受审的独立分支，仅提交根 SECURITY.md。按受信中央提交选择正式模板标签，用 `node scripts/security-policy.mjs prepare <产品工作树> <中央工作树> <模板提交> <受信控制器提交>` 生成并检查公共区块。在 PR 记录标签、完整模板提交及候选文件的 Git blob。保留实际 Copier answers 和现有模板递送分支。治理检查会从受信历史中的正式标签查验公共正文，管理员仍可单独编辑项目段；首次迁移旧政策时须单独审阅原文归属。

## 文件与配置验证

校验器必须比较根 AGENTS.md 与受信模板的完整字节，并验证 UTF-8、无 BOM、LF 和末尾恰好一个换行。载体变化必须进入适用治理检查；首次迁移、新仓接入和后续载体变化应分别完成对应范围盘点。

指令变更必须完成受影响的配置、构建、产物及模板检查。Copilot GitHub review、Codex GitHub review 和 Codex 应用 review 分别核对对应设置、正文及目标覆盖范围；配置确认可复用仍适用的记录和用户确认。复用结果时必须核对对象、提交、入口及相关条件。实际 PR 的审查结果和必要检查按最终待合并提交另行核验。

## 恢复

恢复公共规则时，必须通过受审修正提交及新的模板版本递送恢复后的正文，并保留各仓其他有效内容。恢复 Copilot 组织设置或 Codex 应用偏好时，应分别恢复原文并回读。
